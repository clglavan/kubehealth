Kubernetes triage · local · read-only

See what's broken, not a wall of events.

KubeHealth is one binary you point at your kubeconfig. It groups warnings into one row per broken workload, ranks them by how new they are, and, if you want, asks a small model running on your laptop what to check first.

What you get

Triage first, details one click away.

The namespace list never leaves the screen. Pick a namespace for its live status, pick an object for its ownership chain and full timeline, ask for logs or a root cause without changing pages.

How it handles events

From thousands of events to a ranked list.

One background worker reads the cluster gently; everything else is computed from that cache. Pick a step.

Regular build macOS, Linux, Windows 
tar -xzf kubehealth_*_darwin_arm64.tar.gz
cd kubehealth_*_darwin_arm64
xattr -d com.apple.quarantine kubehealth  # macOS
./kubehealth                    # localhost:8080
Embed build model bundled, AI offline 
tar -xzf kubehealth-embed_*_darwin_arm64.tar.gz
cd kubehealth-embed_*_darwin_arm64
xattr -d com.apple.quarantine kubehealth-embed
./kubehealth-embed              # + local model
KubeHealth-Bench

Does the model actually help? Measured through KubeHealth itself.

The bench replays frozen incidents through the same prompts, evidence, context budget and read-only tools the UI uses, and scores the three things KubeHealth asks a model to do. No cluster needed to run it.

RCA

Find out why it's broken

An agent with four read-only tools and up to five rounds.

  • right root cause and decisive detail
  • right fix, stated as an action
  • investigates when the cause is elsewhere
  • how many lookups, and whether it finishes
